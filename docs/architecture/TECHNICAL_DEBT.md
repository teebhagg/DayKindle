## Additional review dimensions

### Authentication and authorization

- **Verified:** Native Google and Apple token exchange uses a random nonce and Supabase Auth; web cloud auth is disabled. Sync requires matching explicit consent and active user identity.
- **Verified in checked-in SQL:** Planner entity access is user-scoped; writes route through an authenticated bounded RPC. Dashboard requires confirmed user plus an admin table row; aggregate access is separately gated.
- **Needs Validation:** Provider configuration, live RLS, deployed function versions, dashboard admin policy, token revocation, deletion cascade and cross-account behavior were not tested.

### Offline behavior

- **Verified:** Local planner storage exists independently of cloud sync; the account provider detects network state and triggers retries after reconnection/foreground. Sync exposes offline/error/conflict states.
- **Needs Validation:** No airplane-mode, process-kill, cold-start, storage-failure, multi-device or recovery exercise was run. The source-level retry mechanism is not an offline reliability guarantee.

### Accessibility

- **Verified:** Semantic labels/roles, selected states, feedback announcements, contrast-oriented styles and reduced-motion handling appear in shared UI and feature code.
- **Needs Validation:** Dynamic type, screen-reader narration, focus order, native control behavior, chart alternatives and touch target comfort require device testing. Static interface tests do not prove accessible interaction.

### Performance

- **Verified:** HomeScreen is large; context is broad; native snapshot writes replace collections; many UI summaries derive from arrays.
- **Inferred:** These can create maintainability, write-cost or rerender risks at larger data sizes.
- **Verified:** The Expo web export produced a 13,234,362-byte JS entry (2,594,275 bytes gzip). An adapter-based host SQLite test exercised `home-storage.ts` at 129,015 records. The browser smoke had Skia exceptions; the disposable iOS simulator reached the development-client picker but did not load the JS bundle; no Android device was attached.
- **Needs Validation:** No frame timings, React Profiler output, native list-size rendering, startup/save benchmark, browser interaction timing, or memory profile was gathered. Host-SQLite timings do not establish native performance. Measure before optimizing hot paths.

### Security and privacy

- **Verified:** Client uses publishable Supabase configuration; deletion uses a server-side service role; dashboard PostHog API key is read in a server-only module; reviewed product events avoid planner prose.
- **Needs Validation:** No penetration test, data-flow interception, credential review, backup inspection, production retention review or live authorization test was performed. Source review is not a security certification.

## Recommended audit order

1. **Repair runtime and interface contract drift:** resolve the Skia web initialization failure and three failing interface assertions; directly test the primary style in `home-screen-styles.ts` and confirm intended splash/squircle values.
2. **Native runtime and recovery:** connect the Expo development client in disposable iOS and Android profiles; exercise onboarding, create/complete, local save/reload, failed write/retry, recovery, and large-history rendering.
3. **Data integrity:** add deterministic tests for schema migration, recurrence, dedupe, status transitions, template parsing, SQLite write/rollback, and sync idempotency/cursors.
4. **Cloud boundary:** verify deployed Supabase migrations/functions, test RLS and admin denial, then test consent, account switch, offline sync, legacy bootstrap, conflict and deletion in a controlled project.
5. **Accessibility and web matrix:** VoiceOver/TalkBack, dynamic type, keyboard/safe areas, reduced motion, date entry, reminders, browser hydration, responsive routes, and web's unsupported capabilities.
6. **Performance and release baseline:** profile startup, local save, and history/progress rendering on target devices with representative data; then review lockfiles/advisories, native compatibility, environment separation, and deployment provenance.
